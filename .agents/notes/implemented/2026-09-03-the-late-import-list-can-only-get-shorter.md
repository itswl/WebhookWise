---
title: The late-import list can only get shorter
status: implemented
date: 2026-09-03
scope: whole
---

## Decision

Ruff rule `PLC0415` (`import` should be at the top-level of a file) is enabled,
and `[tool.ruff.lint.per-file-ignores]` in `pyproject.toml` names the 245 files
that already had a function-body import on the day it was turned on. The list
was generated by ruff itself, not by hand:

```bash
ruff check --select PLC0415 --output-format=concise . | cut -d: -f1 | sort -u
```

No import was moved. Adding a late import to a file NOT on the list fails
`ruff check .`, which the gate and CI both run. Entries come off the list as
imports move to the top; nothing is ever added to it.

## Why

There are 1791 function-body imports across the repository — 493 in 104
application modules, the rest in tests. The audit found **zero real import
cycles** behind them. They are habit: an import written inside a function
because that is where the name was needed, then copied by the next person
reading that file.

The cost is real but diffuse — import cost paid per call instead of once, an
`ImportError` that surfaces on a code path instead of at startup, and a module
whose dependencies cannot be read from its head. None of that justifies a
1791-line refactor, and a refactor that large is exactly the kind that gets
reverted after it breaks something at 3am.

A ratchet costs nothing and cannot regress. The number is frozen at today's
value; the only direction it can move is down.

## Consequences

- `pyproject.toml` grows a 245-line block that looks alarming and is not. It is
  a snapshot with a date, and the comment above it says so.
- Someone who genuinely needs a late import to break a cycle has to add a file
  to the list, in a diff where a reviewer will see it and ask which cycle. That
  is the intended friction, not an accident.
- New files start clean. The three added in this change were written with
  top-level imports and are not on the list.
- Rejected: a blanket `"tests/*.py" = ["PLC0415"]`. It is shorter and it is a
  fair description of the convention (fixtures import inside the function so the
  import happens after the environment is configured), but it also means a new
  test file can add late imports forever and the count never falls. The list is
  the point.
- Rejected: fixing the 493 application-code cases now. The measurement says
  there is no cycle to preserve, so the refactor is mechanical — but it touches
  104 files, it belongs in its own change, and it can be done a file at a time
  by deleting a line from this list.
